# FIAP — Como construir um portfólio no GitHub que atrai recrutadores

Fonte: https://www.fiap.com.br/radar-tech/post/como-construir-um-portfolio-no-github-que-atrai-recrutadores-e-destaca-seu-perfil/

**Premissa:** o recrutador decide em menos de um minuto, olhando organização e clareza — não o código linha a linha. Portfólio = evidência de que você resolve problemas (demonstrar > afirmar).

## O que o recrutador olha primeiro
- **README de perfil** como vitrine: bio curta e clara (quem é, o que busca), tecnologias, links de contato e LinkedIn.
- **Repositórios fixados (até 6)**: curadoria do seu melhor nível atual; 3–4 projetos sólidos > 60 soltos.
- **Organização visual**: nomes de repositório que fazem sentido, descrições preenchidas, *topics* (tags) configurados.
- **Atividade recente**: não precisa ser intensa, mas precisa existir (gráfico de contribuições = sinal de hábito/consistência).
- Projetos acadêmicos (sprints, trabalho final) bem documentados viram as primeiras peças do portfólio.

## Evite "projetos fantasma"
- Todo repositório precisa de README — recrutadores muitas vezes não leem o código; querem o **porquê**, não só o como.
- Fuja da armadilha do tutorial: personalize (troque o tema, use outra API pública, adicione testes, refatore) e conte isso no README.

## Storytelling no README (o trio)
- **Problema**: que dor você resolveu (de negócio ou técnica).
- **Solução**: por que essa linguagem/banco/arquitetura — 2–3 frases de raciocínio.
- **Resultado**: concreto (métrica de performance, aprendizado, funcionalidade entregue).
- **Demonstração visual**: GIF da aplicação, prints, link de deploy (Vercel/Netlify) para validar em segundos.
- Documentar bem já é uma competência (comunicação, organização do pensamento).

## Red flags
- Falta de **licença** e **.gitignore**.
- **Secrets expostos** (chaves de API, senhas, tokens).
- **Mensagens de commit vagas** ("update", "fix", "ajuste") — use mensagens descritivas.
- **Repositórios abandonados** pela metade — poucos concluídos > muitos interrompidos.

## Checklist em 4 fases
- **Fase 1 – Higiene e curadoria**: arquivar/esconder forks não mexidos e repositórios "hello world".
- **Fase 2 – Padronização da documentação**: READMEs com título, descrição do problema, tecnologias e como rodar.
- **Fase 3 – Visibilidade**: README de perfil, fixar melhores projetos, adicionar topics (pode usar "GitHub Profile Readme Generator", mas personalize).
- **Fase 4 – Networking**: seguir profissionais, acompanhar projetos, contribuir em open source (até uma correção de doc).

**Conclusão:** menos volume, mais relevância — seis projetos bem contados valem mais que sessenta pela metade; o portfólio é vivo e evolui com a carreira.
